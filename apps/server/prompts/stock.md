Stock media: on this machine you can get a sound effect or a photo the footage doesn't have, with the stock script, node "{{stockScript}}". This replaces the SFX row of the skill's §0 defaults table ("Only when tied to a visible event; skip without a library") for sound effects: there is a library now. The rest of that row still holds (a sound effect only when it is tied to a visible event), and so does the Music row: this is not for music.
- Every call takes `"<edit dir>"`: the absolute path of ./edit/, always in double quotes. Run each call as a Bash command of its own, in the foreground, and read the one JSON line it prints: {"ok":true,…}, or {"ok":false,"code":…,"message":…} with a non-zero exit. The script is the only thing that writes edit/stock/: never write, rename, trim or re-encode a file in it. Copy a file you want to use into edit/preview/ (the composition plays from there) and work on the copy.
- The script reads its keys itself. Never read or print a key, and never get stock media any other way (no curl, no other site, no other tool or skill).
- Stock fills what is missing. It never stands in for the client's own footage, graphics or music, and it never goes in a shot the brief or the client's style says to keep plain.
- Sound effects, from Openverse (free, short, CC0, public domain or CC BY). When the cut has a visible event that a sound would help land (a whoosh on a cut or a title, a click on a tapped button, a hit on an impact, a shutter, a room tone under an establishing shot), search with `node "{{stockScript}}" sfx "<edit dir>" "<two to four plain English words, for example whoosh transition>"`. It prints up to 8 candidates, each with a `ref`, a title, its creator, its license and its length in seconds (15 s at most; `--max-seconds 30` allows longer). Pick the one whose title and length fit. If none does, search once more with other words, then go without. Fetch the pick with `node "{{stockScript}}" get "<edit dir>" <ref>`: it prints the `path` of the file in edit/stock/ and its `credit`.
  - Use a few effects, not a bed of them: one per moment, none on top of the words that carry the sentence. They come at whatever loudness their maker used, so measure one and set its level with a gain or a volume lane so it sits under the voice, like any other audio element.
- Photos, from Unsplash. When a shot needs a picture the footage doesn't have (a place, an object, a background for a title or for B-roll over a voiceover) and no graphic in the library fits, search with `node "{{stockScript}}" photo "<edit dir>" "<two to four plain English words>"`, adding `--orientation portrait` for a vertical video (or landscape, squarish). Fetch the pick with `get` the same way. A photo is a still: give it motion over its shot (a slow push-in or drift, which makes this a Mode B edit by the skill), cover the whole frame, and never use a stranger's face to stand for a person in the client's story.
- Limits of a run: 6 searches and 8 files. A search with words it already ran answers from the file ("cached":true) and counts for nothing. An answer with ok false: `rate_limited` or `unavailable` (exit 3) means the service is busy, so go without that item and don't loop; `limit_reached`, `key_missing` or `key_rejected` (exit 2) means don't call it again. Never run the same failing call twice. Say in project.md's Assumptions line what stock media you could not get and why.
- The script records every item in edit/stock/stock.json with its creator and license, and the owner sees them on the job. Don't put a credit on screen unless the brief asks for one. Add one line per item you used to project.md: what it is and where it plays.
