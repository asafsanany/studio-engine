
What is already there, and what goes wrong.
- ./edit/generate/ is your memory. Before each step ls what it needs (story.md, plan.json, voice/, clips/<id>/, footage.mp4, checks.md). What exists is kept: never make a voice take or a scene take again that is there (book answers reused: true with state completed and its file for a take that was made; with a requestId and no file the request is running, so wait for it with jobs_wait and save it; a line call always makes a new take and is charged, so never call it for a line that has a passing take unless the brief’s words changed). A take with no verdict in checks.md is checked now, not made again. To change something, make a new take (--take N+1); nothing is overwritten.
- The plan stays. Change plan.json only where this try needs it (a changed script line, a scene the ladder changed) and say so in project.md.
- An assembled voice stays too. Assemble again only when the pick of a line changed, and then with the same --lead that voice-words.json records as leadMs (none when it has no leadMs), so the opening before the first word is kept.
- A script’s answer on failure is {"ok":false,"code":…,"message":…} and its exit code says what to do:
    exit 3, code unavailable: the service is not answering (a download or an ElevenLabs call). Run the same command once more, then do other work and come back once. Still no: stop calling that service, do not write shots.json, and end with Blocked: and its message word for word.
    exit 2, balance_empty or key_rejected (the voice service, or the picture and clip service when a script says it): stop calling that service at once, do not write shots.json, and end with Blocked: and its message word for word. What was made is kept for the Retry.
    exit 2, over_budget (book): not a blocker. The money is spent: stop spending, keep the best take of everything, leave a scene that has no take out of shots.json (the edit cuts around it), say so in project.md, and go on to the hand-off.
    exit 1, bad_request: you sent something it does not take. Read detail, fix the call and run it again. The same call refused twice: end with Blocked: and its message word for word.
    exit 1, generation_failed (a download that Higgsfield no longer has): make the take again as a new take (--take N+1).
- The Higgsfield connector. A generation that is failed, nsfw or canceled charged nothing: void it, then make it again as a new take (--take N+1) with a plainer prompt; a second failure counts as a failed check: the scene is belowBar, and left out of shots.json when it has no take. If the connector says the plan has no credits left (not enough credits, insufficient credits, out of credits), stop at once, do not write shots.json, and end with the one line Blocked: Higgsfield plan credits are used up: wait for the plan to renew or add credits at higgsfield.ai, then Retry (what was made is kept). If ToolSearch finds no Higgsfield tool, or a tool says it needs signing in or connecting, end with the one line Blocked: Claude cannot reach Higgsfield: reconnect the Higgsfield connector in Claude (Settings, Connectors), then Retry.
- A service whose files are unusable as files (a blank or one-pixel picture, a silent voice file, a clip that will not play) on three calls in a row is broken: stop spending and end with Blocked: and one plain sentence of what came back. A picture or take that is only wrong or poor is a failed check, never a broken service.
- A last line that starts with Blocked: stops the job, so use it only for these: a refusal (its message word for word), the end of the credits, a connector that cannot be reached, the end of the ladder, a brief with no script, a broken service. A scene that came out badly, a missing photo, a budget that runs out part-way are never blockers.
